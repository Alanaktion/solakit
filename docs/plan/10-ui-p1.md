# P1 — operator UI

Status: implemented and HTTP/integration verified; browser visual QA pending.
This phase follows the supplied UI brief. It does not advance live memory,
Discord, scheduled-job, or domain-tool acceptance gates.

- [x] Opaque seven-day in-memory login sessions, constant-time token comparison,
  local five-failure/60-second lockout, HTTPS-aware HttpOnly/Lax cookies, logout,
  expiry and restart invalidation. Existing API Bearer auth remains supported.
- [x] Shared moonlight shell with crescent emoji, native light/dark preference,
  responsive CSS, keyboard focus/labels, and API-reported health chips.
  Chat uses the full viewport, an independently scrolling desktop session sidebar,
  message bubbles, and a bottom-anchored composer. Mobile prioritizes the chat
  with a back link to the session list.
- [x] Sessions list/create with configured profiles from authenticated
  `GET /api/profiles`; API validation remains authoritative.
- [x] Session chat, plain escaped messages, collapsed redacted tool evidence,
  exact status banners and honest unavailable token counts. Composer sends only
  message text and therefore uses the session's configured profile.
- [x] HTMX fragment submission, disabled composer, elapsed wait, no request timeout,
  and connection-error guidance to inspect a run before retrying.
- [x] UI routes call API routes through an in-process ASGI client. No direct Store
  or Execution access and no changes to core loop, storage or prompt assembly.
- [x] Resolved credentials masked at presentation, including transcript text,
  without changing stored/API evidence. Tool arguments/results use redacted logs.
- [x] Local Jinja2 templates/assets included in the Python package, no Node/CDN.
- [x] Integration checks cover auth, cookie flags/revocation/expiry/restart,
  lockout, API/chat parity, validation, escaping, credential masking, tool logs,
  failed backend behavior, static assets, and theme/navigation scope.
- [ ] Visual browser checks in light/dark and mobile. No browser tool is available
  in the managed workspace; HTTP checks are not claimed as browser QA.

Run `uv run sola serve`, open `http://127.0.0.1:8382/`, and sign in with the operator
token. On a disconnected or reloaded chat request, reload to inspect the recorded
state before retrying. Pending runs do not automatically stream or poll in P1.
